# 雅思学习智能体 实施方案（v2.0）

## 0. 目标与范围

- **总体目标**：交付一个完整的雅思学习智能体，支持听/说/读/写/译全模块训练与评估，具备智能诊断、个性化学习计划、多维度能力提升、社区互动等核心功能，实现从基础备考到高分冲刺的全周期覆盖。
- **首期MVP**（优先闭环）：口语全真模拟 + 自动评分 + 可操作改进清单 + 7天训练计划 + 基础诊断测评 + 智能错题管理。
  - 端到端延迟（P95）：ASR < 1.5s；评分 < 2s；总 < 3s。
  - 评分一致性：与人工考官加权Kappa/Quadratic Weighted Kappa ≥ 0.80。
  - 用户价值：一键模拟 + 即时报告 + 分层训练建议 + 次日复练提醒 + 个性化学习路径。
- **目标用户**：覆盖雅思新手、瓶颈期考生、冲刺高分考生、自学乏力考生、口语专项强化考生等5类用户。

## 1. 里程碑与时间线（24 周）

### 第一阶段：基础建设（6-8周）

- 第1-2周：需求冻结与MVP细化；选型与成本测算；数据与合规方案确定。
- 第3-4周：系统骨架搭建（服务划分、接口骨架、身份与存储）、ASR/TTS联通。
- 第5-6周：用户画像与诊断测评系统实现（自适应测试、能力评估、报告生成）。
- 第7-8周：个性化学习计划生成与提醒系统（智能计划、多渠道提醒、执行跟踪）。

### 第二阶段：核心功能完善（8-10周）

- 第9-10周：口语MVP实现（Part1/2/3流程、计时、录音、转写、初版评分与报告）。
- 第11-12周：评分标定与评测集搭建；QWK≥0.8 达标；用户画像与建议生成优化。
- 第13-14周：错题管理系统（智能收集、错因分析、间隔重复复习）。
- 第15-16周：词汇学习模块（智能词汇本、场景词汇、学习策略）。
- 第17-18周：口语对练与作文互评功能（角色扮演、话题覆盖、互评系统）。

### 第三阶段：增值功能（6-8周）

- 第19-20周：学习社区（话题讨论、问答互助、经验分享）。
- 第21-22周：游戏化激励系统（积分、等级、成就、排行榜）。
- 第23-24周：学习小组与前端应用完善（组内任务、打卡排行、Web/移动端适配）。

### 关键里程碑

- 第8周：基础系统上线（用户画像、诊断、计划、提醒）。
- 第18周：核心功能上线（口语、写作、错题、词汇）。
- 第24周：完整产品上线（社区、游戏化、小组、前端）。

### 2.2 智能体系统架构

- **通用智能体（CommonAgent）**：作为入口，负责路由和协调各专用智能体。
- **专用智能体**：
  - **SpeakingAgent**：处理口语相关任务，包括模拟考试、评分、反馈。
  - **WritingAgent**：处理写作相关任务，包括批改、思路生成、范文分析。
  - **ReadingAgent**：处理阅读相关任务，包括文章分析、题型训练。
  - **ListeningAgent**：处理听力相关任务，包括音频处理、题型训练。
  - **TranslationAgent**：处理翻译相关任务，包括双向翻译、评分反馈。
  - **PlanningAgent**：处理学习计划相关任务，包括计划生成、调整、跟踪。
  - **DeepSearchAgent**：处理深度搜索任务，包括多源信息整合、迭代搜索。

### 2.3 数据流与通信

- **消息传递**：智能体之间通过消息队列进行通信。
- **状态共享**：通过Redis和数据库共享用户学习状态。
- **任务协作**：复杂任务由多个智能体协作完成。

## 3. 技术选型

### 3.1 核心技术栈

- **语音技术**：
  - ASR：优先云服务（阿里云、腾讯云），可选 Whisper-large-v3-turbo（离线备选）。
  - TTS：云TTS（多音色/高自然度），本地轻量TTS（如PaddleTTS）兜底。

- **大语言模型**：
  - 主力LLM：可商用合规的GPT-4o/Claude/国产合规大模型（如文心一言、通义千问）。
  - 小模型：用于要素抽取、一致性校验、快速响应。

- **后端服务**：
  - 框架：Python FastAPI。
  - 任务编排：Celery/Arq + Redis。
  - 流式传输：WebSocket。
  - 认证：JWT/OAuth2。
  - 缓存：Redis Cluster。
  - 队列：Redis Streams/Kafka。

- **前端应用**：
  - Web：React/Next.js。
  - 移动：Flutter/React Native（二选一）。
  - 小程序：微信小程序。

- **数据存储**：
  - 关系型：PostgreSQL（生产）、SQLite（开发/轻量）。
  - 向量数据库：Milvus。
  - 对象存储：S3/OSS。
  - 搜索：OpenSearch。

- **智能体框架**：
  - LangChain 或自定义框架。
  - 工具集成：检索、搜索、计算。

- **监控与运维**：
  - 指标：Prometheus。
  - 日志：ELK/ClickHouse。
  - 追踪：OpenTelemetry。
  - 看板：Grafana。
  - LLMOps：提示管理、模型评估、版本控制。

### 3.2 技术选型考量

- **性能与成本平衡**：云服务与本地部署结合，高峰期扩容，低峰期缩容。
- **合规与安全**：选择符合本地法规的服务提供商，数据加密存储与传输。
- **可扩展性**：模块化设计，微服务架构，便于未来功能扩展。
- **开发效率**：选择成熟的框架和工具，减少重复开发。

## 4. MVP 范围与用例

### 4.1 核心功能范围

- **诊断与测评**：
  - 初始水平诊断（自适应测试，覆盖听说读写）
  - 薄弱点分析与可视化报告
  - 能力雷达图与进步追踪

- **口语训练**：
  - Part 1/2/3全真模拟
  - 实时录音与转写
  - 四维评分（流利连贯、词汇、语法、发音）
  - 详细改进建议与练习清单

- **个性化学习计划**：
  - 基于诊断结果的智能计划生成
  - 每日任务分解与提醒
  - 学习进度跟踪与计划调整

- **错题管理**：
  - 智能错题收集与分类
  - 错因分析与同类题推荐
  - 基于遗忘曲线的间隔复习

- **词汇学习**：
  - 智能词汇本（自动收录生词）
  - 场景化词汇学习
  - 多种测试模式（拼写、选择、填空）

### 4.2 关键用例

#### 用例1：新用户首次使用

1. **水平诊断**：用户完成自适应诊断测试（15-20分钟）。
2. **能力评估**：系统生成详细的能力报告，包括总分、分项分数、薄弱点。
3. **计划生成**：基于诊断结果和目标分数，生成个性化学习计划。
4. **开始学习**：用户按照计划开始每日学习任务。

#### 用例2：口语练习

1. **选择话题**：用户选择口语练习话题或使用系统推荐。
2. **模拟考试**：系统模拟Part 1/2/3流程，进行录音和转写。
3. **智能评分**：系统给出四维评分和详细评语。
4. **改进建议**：生成可操作的改进清单和练习建议。
5. **计划调整**：基于练习结果，自动调整学习计划。

#### 用例3：错题复习

1. **错题收集**：系统自动收集用户在练习中做错的题目。
2. **错因分析**：AI分析错误原因，提供详细解释。
3. **间隔复习**：根据遗忘曲线，智能安排复习时间。
4. **掌握度标记**：用户标记已掌握的题目，减少复习频率。

#### 用例4：词汇学习

1. **生词收录**：系统自动收录阅读和听力中的生词。
2. **场景学习**：按场景分类词汇，提供真实语境例句。
3. **智能测试**：基于掌握情况，动态调整测试难度。
4. **复习提醒**：根据遗忘曲线，发送复习提醒。

## 6. 评分与标定

### 6.1 口语评分

- **指标定义**：对齐官方Band Descriptors（Fluency & Coherence, Lexical Resource, Grammatical Range & Accuracy, Pronunciation）。
- **评测集**：多考官双盲打分集（≥500样本，覆盖不同口音与话题难度）。
- **评估指标**：QWK、皮尔逊相关、MAE（回归到Band）；分布一致性检验；置信区间展示。
- **校准方法**：等分回归 + 温度缩放（或Platt）以稳定Band离散化；灰度上线前后对照。
- **漂移监控**：上线后按周抽检再标注；阈值外自动降级为“建议型反馈”，收敛后恢复打分。

### 6.2 写作评分

- **指标定义**：对齐官方Band Descriptors（Task Response, Coherence & Cohesion, Lexical Resource, Grammatical Range & Accuracy）。
- **评测集**：多考官双盲打分集（≥300样本，覆盖不同话题与题型）。
- **评估指标**：QWK、皮尔逊相关、内容一致性、结构逻辑性。
- **校准方法**：同口语评分。
- **漂移监控**：同口语评分。

### 6.3 阅读与听力评分

- **指标定义**：基于正确题数的分数转换，参考官方评分标准。
- **评测集**：标准化题库，覆盖不同难度级别。
- **评估指标**：准确率、一致性、时间效率。
- **校准方法**：分数转换表校准，确保与官方标准一致。

### 6.4 翻译评分

- **指标定义**：从准确性、流畅度、语法、词汇四个维度评估。
- **评测集**：多译者标注集（≥200样本）。
- **评估指标**：一致性、准确性、流畅度。
- **校准方法**：多维度评分融合。

### 6.5 标定流程

1. **数据收集**：采集真实用户数据与专家标注。
2. **模型训练**：使用标注数据训练评分模型。
3. **模型评估**：使用评测集评估模型性能。
4. **校准调优**：调整模型参数，确保评分一致性。
5. **上线监控**：实时监控评分漂移，定期再标定。

### 6.6 质量目标

- 口语/写作评分：QWK ≥ 0.80
- 阅读/听力评分：与官方标准误差 ≤ 0.5分
- 翻译评分：与人工评分一致性 ≥ 85%
- 评分延迟：P95 < 2秒

## 8. 安全与隐私

### 8.1 数据安全

- **数据分级与分类**：根据敏感度对数据进行分级（PII、业务数据、公开数据），实施差异化保护。
- **加密策略**：
  - 静态加密：使用KMS对存储数据进行加密。
  - 传输加密：所有API调用使用TLS 1.3。
  - 端到端加密：对敏感用户数据（如录音、作文）实施端到端加密。
- **访问控制**：
  - 最小权限原则：各服务仅能访问所需数据。
  - 基于角色的访问控制（RBAC）：为不同用户和服务分配适当权限。
  - 服务间通信：使用mTLS确保服务间通信安全。

### 8.2 隐私保护

- **PII处理**：
  - 数据最小化：仅收集必要的个人信息。
  - 匿名化：对用户数据进行匿名化处理，减少隐私风险。
  - 数据生命周期管理：制定明确的数据保留和删除策略。
- **用户控制**：
  - 数据访问：用户可查看和导出个人数据。
  - 数据删除：用户可请求删除个人数据。
  - 隐私设置：提供详细的隐私设置，允许用户控制数据使用方式。
- **透明度**：
  - 隐私政策：制定清晰的隐私政策，告知用户数据使用方式。
  - 数据处理记录：记录数据处理活动，确保可追溯性。

### 8.3 合规要求

- **法规遵循**：
  - 遵循所在地法律法规（如GDPR、CCPA、本地数据保护法规）。
  - 定期进行合规评估和更新。
- **数据保护影响评估（DPIA）**：
  - 对高风险数据处理活动进行DPIA。
  - 根据评估结果采取相应的风险缓解措施。
- **安全审计**：
  - 定期进行安全审计和渗透测试。
  - 及时修复发现的安全漏洞。

### 8.4 社区内容安全

- **内容审核**：
  - 建立自动化内容审核系统，识别和过滤违规内容。
  - 人工审核机制，处理复杂或争议性内容。
- **用户举报**：
  - 提供便捷的用户举报渠道。
  - 建立快速响应机制，及时处理举报内容。
- **安全提示**：
  - 向用户提供安全使用社区的提示和建议。
  - 定期进行安全意识教育。

### 12.3 验收流程

1. **功能测试**：验证所有功能模块正常运行。
2. **性能测试**：验证系统性能指标达标。
3. **安全测试**：验证系统安全性和隐私保护措施。

6. **灰度发布**：小流量试运行，监控系统表现。
7. **正式验收**：通过所有测试和审查，签署验收报告。
